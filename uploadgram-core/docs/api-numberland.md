# تحلیل API نامبرلند (numberland.ir)

> این فایل فقط **تحلیل** مستندات رسمی نامبرلند است (از صفحه developers).
> کد فعلی `class-ug-provider-numberland.php` با این مستندات **مطابقت ندارد** و
> هنگام شروع پیاده‌سازی باید کامل بازنویسی شود.

## پایه

- **Base URL:** `https://api.numberland.ir/v2.php`
- **متد HTTP:** `GET`
- **قالب فراخوانی:**
  `https://api.numberland.ir/v2.php/?apikey=[API_CODE]&method=[METHOD]&...`
- **خروجی:** JSON
- **قاعده خطا:** فیلد `RESULT` اگر **منفی** باشد یعنی خطا. مقدار مثبت/عدد
  معتبر یعنی موفق. فیلدهای پاسخ **حروف بزرگ** هستند
  (`RESULT` / `ID` / `NUMBER` / `AREACODE` / `AMOUNT` / `CODE`).

## متدها

| method | پارامترها | توضیح | پاسخ موفق |
|--------|-----------|-------|-----------|
| `balance` | — | موجودی حساب | `RESULT` = موجودی |
| `getinfo` | — | لیست سرویس‌ها/کشورها + قیمت و موجودی. هر آیتم یک `id` دارد که همان **SERVICE_COUNTRY_ID** است | آرایه‌ای از آیتم‌ها |
| `getnum` | `sid=[SERVICE_COUNTRY_ID]` | خرید/رزرو یک شماره | `RESULT`, `ID`, `NUMBER`, `AREACODE`, `AMOUNT` |
| `checkstatus` | `id=[ID]` | وضعیت شماره/دریافت کد | `RESULT` (کد وضعیت ۱ تا ۶) + `CODE` وقتی پیامک رسید |
| `cancelnumber` | `id=[ID]` | لغو شماره (بازگشت وجه اگر کدی نیامده) | `RESULT` |
| `bannumber` | `id=[ID]` | بن/رد شماره (شماره خراب) | `RESULT` |
| `repeat` | `id=[ID]` | درخواست مجدد همان شماره برای پیامک بعدی | `RESULT` |
| `closenumber` | `id=[ID]` | بستن/آزاد کردن شماره | `RESULT` |
| `getcountry` | — | لیست کشورها | آرایه کشورها |
| `getservice` | — | لیست سرویس‌ها | آرایه سرویس‌ها |

## کدهای وضعیت `checkstatus` (RESULT ۱ تا ۶)

- `1` — در انتظار دریافت پیامک (هنوز کدی نیامده)
- `2` — شماره آماده، منتظر پیامک
- `3` — پیامک/کد دریافت شد (فیلد `CODE` پر است)
- `4` — شماره لغو شده
- `5` — شماره بن شده
- `6` — منقضی/بسته شده

> نگاشت به وضعیت داخلی: `1/2` → `awaiting_otp`، `3` → `completed`،
> `4/5/6` → `failed/cancelled`.

## کدهای خطا (RESULT منفی)

| کد | معنی |
|----|------|
| `-901` | apikey نامعتبر |
| `-902` | دسترسی مسدود / IP مجاز نیست |
| `-990` | خطای عمومی سرور |
| `-900` | پارامتر نامعتبر |
| `-202` | موجودی کافی نیست |
| `-204` | سرویس موجود نیست |
| `-205` | شماره موجود نیست |
| `-210` | id نامعتبر |
| `-211` | عملیات غیرمجاز روی این id |
| `-212` | شماره قبلاً بسته شده |
| `-304` | محدودیت درخواست (rate limit) |

## نکات پیاده‌سازی (برای بازنویسی provider)

1. `create_order()` باید `method=getnum&sid=...` بزند (نه `getnumber`).
   ورودی سرویس همان **SERVICE_COUNTRY_ID** است که از `getinfo` می‌آید.
2. `order_status()` باید `method=checkstatus&id=...` بزند و `RESULT` عددی را
   به وضعیت داخلی نگاشت کند؛ کد از فیلد `CODE`.
3. `cancel()` → `cancelnumber`. علاوه بر آن متدهای `bannumber`, `repeat`,
   `closenumber` را هم اضافه کنیم (اکشن‌های پنل کاربر).
4. تشخیص خطا: `RESULT < 0` → خطا (نه فیلد `status`). پیام خطا را از جدول بالا
   نگاشت کنیم.
5. فیلدها **حروف بزرگ** خوانده شوند (`$data['NUMBER']` نه `number`).
6. صفحه/API فقط با **IP ایران** پاسخ می‌دهد؛ در محیط تست بیرون از ایران باید
   حالت `is_test` یا موک داشته باشیم.

## وضعیت فعلی کد

`class-ug-provider-numberland.php` هنوز از `getnumber` / `getsms` / `cancel`
و فیلدهای حروف کوچک استفاده می‌کند → **نیازمند بازنویسی کامل** هنگام شروع.
